## Requirements

### Requirement: Portable onedir archive
The release build SHALL produce `dist/IconReplacer-<version>-win64.zip` and a matching
`.sha256` file. The archive SHALL contain one top-level folder `IconReplacer-<version>-win64/`
holding `IconReplacer.exe`, `iconreplacer-cli.exe`, `_internal/`, `LICENSE`,
`THIRD_PARTY_NOTICES.md` and `README-PORTABLE.txt`. It SHALL NOT require an installer,
administrator rights or a Python installation.

#### Scenario: Archive layout
- **WHEN** the release build finishes
- **THEN** the zip has exactly one top-level folder named `IconReplacer-<version>-win64` that contains the files listed above

#### Scenario: Checksum
- **WHEN** the archive is written
- **THEN** a `.sha256` file holds the SHA-256 of the zip in `<hash> *<name>` form

### Requirement: Console output companion
The GUI executable SHALL be a windowed program. A console companion `iconreplacer-cli.exe`
built from the same code SHALL print `--version`, `--status`, `--register` and `--unregister`
results to standard output. When the companion registers the Explorer verb, the registered
launcher SHALL be `IconReplacer.exe`, never the companion.

#### Scenario: Version from the build
- **WHEN** `iconreplacer-cli.exe --version` runs from the built folder
- **THEN** it prints `IconReplacer <MAJOR>.<MINOR>.<PATCH>.<BUILD>` equal to the single version source and exits 0

#### Scenario: Registration launcher
- **WHEN** the companion builds the registration command in a frozen environment
- **THEN** the command is `"<folder>\IconReplacer.exe" --folder "%1"`

### Requirement: Embedded Windows metadata
The executables SHALL embed a VERSIONINFO resource generated from the single version source:
FileVersion and ProductVersion `MAJOR.MINOR.PATCH.BUILD`, CompanyName "IconReplacer contributors",
ProductName, LegalCopyright mentioning the MIT license and OriginalFilename. They SHALL embed an
original application icon generated by code that contains no third-party artwork.

#### Scenario: Version info content
- **WHEN** the version resource is generated
- **THEN** it contains the four-part version, the company, product name, copyright and original file name

#### Scenario: Application icon
- **WHEN** the icon generator runs
- **THEN** it writes a valid ICO with at least the sizes 16, 32, 48, 64, 128 and 256

### Requirement: Complete and lean payload
The build SHALL bundle every non-Python file under `src/iconreplacer/` (including JSON data and
compiled `.qm` translations) without a hard-coded file list, the Qt `windows` platform plugin,
the styles and the image-format plugins `qico`, `qsvg`, `qicns`, `qwebp`, `qjpeg`, and QtSvg.
It SHALL exclude unused heavy Qt modules and plugins.

#### Scenario: Data files collected
- **WHEN** the data-file list is computed
- **THEN** it contains the catalog `*.json` files and every compiled `*.qm`, and no `.py` file

### Requirement: Portable data location
When frozen, the application directory SHALL be the executable folder, so user data lives in
`data\` next to the executable when that folder is writable, and in `%LOCALAPPDATA%\IconReplacer`
otherwise.

#### Scenario: Frozen data root
- **WHEN** the built executable runs without `ICONREPLACER_HOME` and its folder is writable
- **THEN** the data root is `<exe folder>\data`

### Requirement: Licensing notices and redistribution limits
The archive SHALL ship the MIT license and a third-party notices file covering PySide6/Qt
(LGPL-3.0, dynamically linked and replaceable, where to get the sources), Python (PSF),
the PyInstaller bootloader exception and the icon-source licensing caveats. The archive SHALL
NOT contain Microsoft icon artwork.

#### Scenario: Notices content
- **WHEN** the archive is inspected
- **THEN** `THIRD_PARTY_NOTICES.md` mentions LGPL-3.0, Qt, Python, PyInstaller and Microsoft icons referenced in place

### Requirement: Failing build
The release build SHALL exit non-zero on any failed step, including a smoke test whose
`--version` output differs from the version source.

#### Scenario: Smoke mismatch
- **WHEN** the built executable prints a different version than the source
- **THEN** the build exits non-zero and writes no archive
